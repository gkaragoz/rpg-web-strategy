# Simulation

- `src/sim/battle.ts` owns the step loop and the persistent state (the `Battle` class); the rest of the combat code is split into function modules that take the battle as first argument: `battleConfig.ts` (config, constants, capacities, `terrainFor`), `battleAi.ts` (threat, kiting, chase, leash, target choice), `battleSkills.ts` (attacks, skills, projectile landing), `battleDamage.ts` (damage, death, zones, comedy physics), `battleEffects.ts` (status effects, gathering), `battleSetup.ts` (spawn layouts). Members the modules need are marked `@internal`. It owns the step loop: targeting, movement on the grid (`grid.ts`), attacks, skills, projectiles (`projectiles.ts`), terrain effects (`terrain.ts`).
- Unit state is struct-of-arrays in `units.ts` (typed arrays) for speed; stats are normalized from the raw roster numbers there.
- **Determinism**: same seed + same inputs ⇒ same state on every client. Randomness only via `Mulberry` (`random.ts`). The state hash is compared every 60 steps online.
- `snapshot.ts` serializes/restores a battle (used for late joiners and desync recovery); new state must be included in `serialize/restore/hash`.
- Stall detector (`testing/stall.ts`) and fuzz tests guard against fights that never end.
- Rules for editing: `.claude/rules/sim-determinism.md`.

## Map guarantees (`Terrain.fixPockets`, `mapsanity.test.ts`)
Every generated map is playable: no walkable tile is unreachable from the main area. Closed-in ground (a plateau or valley ringed by cliffs, an island) gets a ramp when one fits (a gradual slope cut into the higher side; the tiles beside it that end up too high become cliffs), otherwise it is sealed as an obstacle and dressed with rocks (`dressSealed`), e.g. the ridge walls of the valley layout. Everything is applied to the point-mirrored tile too, so maps stay fair, and it only depends on the seed, so all online clients build the same map. The sanity test sweeps all presets, layouts, reliefs and rivers over sizes and seeds: no unreachable walkable ground, point symmetry, bounded sealed ground, roomy team zones for 2/4/6 teams.


## Game modes (`src/sim/modes/`)
`BattleConfig.rules` (`GameModeId`: `classic | hill | vip | ctf`, default `classic`; not to be confused with `BattleConfig.mode`, the launch kind) selects a `ModeRules` instance (`modeFor(id)`, one per `Battle`). All modes are autonomous: nothing is ordered during a battle.
- Hooks: `init(b)` at the end of `Battle.reset`, `step(b, dt)` once per step after the normal logic while the battle is undecided, `winner(b)` (team, -2 draw, undefined: go on) after the last-team-alive check, `serialize()/restore()` (plain numbers, stored in `snapshot.extra.mode`), `hud(b)` (pure `ModeHud` data for the UI) and `scores()`. Non-classic mode state and the team goals are part of `Battle.hash`; classic hashes are unchanged (`golden.test.ts`). The `checkDraw` no-damage draws only apply in classic.
- **Goal hook**: `Battle.teamGoalX/Y/teamHasGoal` (per team, serialized). `marchToEnemy` (units without a target) heads for the team goal when set, otherwise for the nearest enemy centroid as before. Fighting and target choice are unchanged.
- **King of the Hill** (`hill.ts`): 3 control points (map centre plus two flanks, ~28% of the map size from the centre perpendicular to the spawn axis; always on walkable tiles of the main region, see `hillControlPoints`), capture radius `max(3.5, size * 0.06)`. Every 10 steps the owner of a point is the team with strictly the most living units inside it (equal top counts: contested, -2; nobody inside: the owner keeps it). Each owned point gives +1 point per second, counted in whole steps (no float drift). First to 100 points wins (a tie at the top continues), after 600 s the leader wins (tie: draw). Each team's goal is the nearest point it does not own. `Battle.modeHud()` / `modeScores()` expose the display data.
- **VIP** (`vip.ts`): every team has one VIP unit. When it dies (any path through `killUnit`, via the optional `ModeRules.onKill` hook) its whole team dies at once through the normal kill path (counters, `death` events and meter kill credit go to the killer of the VIP); the usual last-team-standing logic then decides. The classic no-damage draws are bypassed; after 600 s the team whose VIP has the highest hp fraction wins (tie: draw, -2). Which unit: `BattleConfig.vips[team]` is a **layout index** (k-th group of 4 floats of `config.layout`) or -1 for auto (highest max HP, ties: lowest unit index; summon-pool units are never picked). `spawnLayout` skips entries whose spot has no walkable tile, so layout index != unit index: `Battle.layoutUnits[layoutIndex]` (-1 when skipped) maps it at `reset`. An out-of-range, skipped, foreign-team or non-integer pick falls back to auto; demo/bench layouts always auto-pick. State (VIP unit index and an out flag per team) goes into `serialize/restore/hash`. `Battle.vipUnits()` (Int32Array, length MAX_TEAMS, -1 none) and `vipUnitsOf(modeHud)` give the unit indices to a renderer; `ModeHud` is `{ kind: 'vip'; teams: [{ unit, hp (0..1), alive }] x MAX_TEAMS; timeLeft }`. The worker frame carries it in `F_MODE_ON = 2` + `F_VIP_BASE` (hill layout unchanged). No scores. The offline studio builds `config.vips` from its `PlacedUnit.vip` flags (layout order = placement order).
- **Capture the Flag** (`ctf.ts`): each team has one flag at a home base = centroid of its initial (alive, non-pool) units snapped to the nearest walkable tile of the main region (`ctfBasePoint`), base radius `ctfRadius(size) = max(3, size * 0.05)`. Every 5 steps (steps 1, 6, ...) units are scanned in index order: the first living, non-summoned unit of another team within the radius of a flag at home becomes its carrier (lowest index wins ties; a unit carries one flag; pool/dormant/summoned units never carry). New optional hook `ModeRules.drive(b, i, dt)` (called from `Battle.updateUnit` after the stun/fear checks, only for modes that define it): a carrier ignores the fight and `queueMove`s to its own base at normal speed. Every step a carrier inside its own base radius scores (`captures` +1), the flag returns home and the unit is released; a dead carrier (`onKill`) returns the flag at once. Goals (re-evaluated every 5 steps): a team with a carrier heads for its own base (escort), else if its flag is carried it hunts the carrier's current position, else the nearest enemy flag at home. First to 3 captures wins (a tie at the top continues); after 600 s the most captures win (tie or all zero: draw, -2); last team standing wins as usual; the classic no-damage draws are bypassed. State (captures, carrier per flag, base x/y/exists, radius) is in `serialize/restore/hash`. `scores()` = captures per team.
  `ModeHud` ctf: `{ kind: 'ctf'; captures: number[] /* MAX_TEAMS */; target: 3; radius: number; flags: Array<{ team: number /* flag owner */; x; y; carrier: number /* unit index or -1 */; carrierTeam: number /* -1 at home */ }> /* one per team with units, team order; x,y = base at home, else the carrier's current position */; timeLeft }`. Worker frame: `F_MODE_ON = 3`, captures in `F_SCORE_BASE`, 5 values per team from `F_CTF_BASE` (owner team or -1, x, y, carrier, carrierTeam), `F_CTF_RADIUS`; `F_LEN` is 105 (hill/vip layouts unchanged).
- Tests: `modes.test.ts`, `modesvip.test.ts`, `modesctf.test.ts` (sim), `netvip.test.ts` (online).
