# Online play

- **Topology**: one host (authoritative), many guests and spectators. Transports: LAN WebSocket (`scripts/lan.mjs`, also served by `vite preview`), Cloudflare relay (`relay/`), WebRTC (`peerTransport.ts`).
- **Lobby** (`host.ts` `HostLobby`): players, teams, settings, gold budgets (`economy.ts`), placement zones, kicks. Guests send intents; the host validates and broadcasts the state.
- **Flow**: lobby → placement (own zone, gold budget, live cursors) → ready → battle (lockstep) → results. Setup failures return to a rejoinable state.
- **Lockstep** (`lockstep.ts`, `lockstepSim.ts`): host broadcasts ticks/speed/pause; guests step in sync; checksum mismatch ⇒ snapshot resync. Large messages are chunked (`chunk.ts`).
- **Comedy options**: *physics* changes the simulation (big hits launch units, landing in water drowns them), so it is a lobby setting fixed at game start; *view* (ragdolls, comic text, cartoon sounds) is look-only. Both are host-only: guests see them disabled in the lobby, and during a battle only the host can switch the view (`cmd.comedyVisual` then a `comedyView` broadcast; everybody follows, late joiners get it through `init.comedyVisual`).
- **Protocol**: `PROTOCOL` in `protocol.ts` (currently 17). Bump on any wire change. Messages carry codes, receivers translate.
- UI: `src/app/online/` (`online.ts` controller, lobby, placement, badge, cursors).
- Rules: `.claude/rules/online-protocol.md`; manual test: `online-smoke-test` skill.

## Game modes
`LobbySettings.gameMode` (`'classic' | 'hill' | 'vip' | 'ctf' | 'siege' | 'horde' | 'lanes'`, default `classic`) is host-only like the other settings: `HostLobby.onSettings` ignores unknown values and a real change clears the ready flags. `start()` copies it into `GameInit.gameMode`; `battleConfig(start)` turns it into `BattleConfig.rules`, so every client builds the same rules. The `result` message (and `HostLobby.finish`) carries optional `scores` (points per team for hill, captures per team for ctf); the host's `LockstepRunner` reads them from `SimLike.scores` (`Battle.scores`, `WorkerSim.scores`). Added in protocol 12. Siege (protocol 14) adds `LobbySettings.siegeDefender` (team index, default 0; the host ignores non-integers outside 0..5) which `start()` clamps into `0..teams-1` and copies into `GameInit.siegeDefender` (0 in other modes); `battleConfig` passes it as `BattleConfig.siegeDefender`. The core kind is a structure and unbuyable, so a `place` for it fails with `unbuyable`. Horde (protocol 15) is a co-op mode: every placed team is an ally against an AI team that is not a player (`GameInit.teams` / `BattleConfig.teamCount` stay the human count, the horde is team index `teams`; result `winner` is a human team on victory or the horde index `teams` on defeat, `scores` = `[waves, ..., 0]`). The horde needs the sixth team index, so a room with 6 players cannot start it: `HostLobby.canStart()` is false and a host `start` is answered with `{ t: 'startFail'; reason: 'hordeTooManyTeams' }` (`StartFailReason`, sent to the host only, stored in `ClientModel.startFailed`; the UI shows `online.reason.hordeTooManyTeams`); the room stays in the lobby. Lane Conquest (protocol 16) is a two-team mode: with any other player count `canStart()` is false and `start` is answered with `startFail` / `lanesNeedTwoTeams` (the studio checks `teamCount` itself). The host plays it on the dedicated `lanes` layout: `start()` raises the map size to at least 80 (`LANES_MIN_SIZE`), replaces the recipe by `lanesSpec(spec)` (only the biome is kept; a random map only draws the seed) and puts that spec and size in `GameInit`, so the placement terrain, the zones (left half = team 0, right half = team 1, `laneZones`) and `battleConfig(start)` agree on every client. The map picker and the map size setting therefore do not apply to a lanes room.

Maps per mode (protocol 17): a room only plays on a map its mode can use (`src/sim/mapModes.ts`, see docs/SIMULATION.md). `onSettings` fits `settings.map` with `fitMapToMode` whenever the host changes `gameMode` or `map` (the new `state` goes to everybody, so lobbies update at once; Lane Conquest keeps the stored pick) and, when a fixed map was replaced, sends the host only `{ t: 'mapFitted'; presetId; mode }` (stored in `ClientModel.mapFit`; the UI toasts the preset name). `start()` draws random rooms with `randomSpecFor(mode, rng)` and fits once more, so `GameInit.spec` is always compatible. The mode layouts (`arena`, `forts`, `plateau`) are valid in `sanitizeSpec`, hence the version bump.
**VIP (protocol 13).** During placement a player marks one of their own placed units with `{ t: 'vip', id }` (`id` = `PlacedItem.id`, -1 clears). The host (`HostLobby.onVip`, `vipByTeam`) accepts it only in a `vip` room, in the `placing` phase, from a `player` who is not ready, for a unit of their own team; anything else (bad shape, foreign or unknown unit, rate limit) leaves the choice unchanged. Every `vip` message is answered to the sender only with `{ t: 'vipSet', id }` (own team's current VIP, -1 none; no failure codes, the answer corrects the client). `vipSet` is also sent after the VIP unit is unplaced (choice cleared), after a rematch (units and VIP are kept) and when a player (re)joins during placement (after the placed batches); it is never sent to spectators, and other players' picks are not revealed before the battle. A kicked/disconnected player keeps their ghost units, so the pick stays. `BattleStart.vips` (length `init.teams`) carries every team's pick as a layout index (the layout is sorted by unit id) or -1; `battleConfig(start)` copies it to `BattleConfig.vips`, so host, guests and late joiners (the start is in `welcome`) build identical configs. `OnlineModel.vip` mirrors the last `vipSet`.
